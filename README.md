# COOKr

*Cook what you already have.* — Cook and Flame studio

A recipe shelf of 24 photographed, tested recipes you can filter by cuisine and by the time
of day you are actually going to eat, plus weekly community cooking challenges, chef levels
and badges for the nights you cook rather than order in.

## What is in it

**The shelf.** 24 recipes, each with a generated photo, full ingredients and method, a
per-serving macro breakdown, a contributor and a "if it goes wrong" note. Every recipe
carries several times of day, because a Spanish tortilla is lunch *and* it is dinner and the
sidebar should find it under both.

**The sidebar.** Filter by time of day (breakfast → late-night), cuisine (14 of them), the
time you actually have, and how you eat. Cuisines are OR'd, tags are AND'd, and all of it
lives in the URL — so a filtered shelf is a link you can send someone, and the back button
does what you expect.

**Weekly challenges.** One community prompt a week ("Healthy Comfort Food Week", "Five
Ingredients or Less", and four more), chosen from a fixed rota by ISO week number, so
everybody sees the same prompt and a new one opens every Monday with no scheduler. Cook it,
upload a photo, and the community votes — one vote per plate, never your own.

**Chef levels and badges.** XP for cooking at all, for a cuisine you have never touched, for
hitting a protein goal and for stringing nights together. Eight ranks from Kitchen Novice to
Executive Chef, and 12 badges including Pantry Cleared and Heritage Cook.

**Leaderboards.** All-time Chef Level, plus most cooked, most high-protein and most diverse
for the current challenge week.

## Stack

| Layer | Choice |
|---|---|
| Framework | TanStack Start (React 19, TanStack Router) |
| Build | Vite 7 |
| Styling | Tailwind CSS 4, Fraunces + Karla |
| Data | Netlify Database (Postgres) via Drizzle ORM |
| Files | Netlify Blobs for challenge photos |
| Images | Netlify Image CDN, originals generated with Gemini through the Netlify AI Gateway |
| Language | TypeScript 5.9 |

## Layout

```
db/schema.ts                  eight tables: users, sessions, cook logs, XP, badges,
                              challenge entries, votes, ratings
netlify/database/migrations/  generated by drizzle-kit, applied by Netlify at deploy
src/data/                     recipes, challenges, levels and badges — plain data
src/server/auth.server.ts     registration, login, sessions
src/server/kitchen.server.ts  XP, streaks, badge rules, challenges, leaderboards
src/server/kitchen.functions.ts  the RPC surface routes and components call
src/lib/shelf.ts              filtering and sorting
src/components/ShelfSidebar.tsx  the cuisine / time-of-day filters
src/routes/                   the pages
scripts/generate-images.mjs   one-off photo generation
```

## Running it

```sh
pnpm install
netlify dev
```

`netlify dev` is the one to use rather than `vite dev` — the database connection, Blobs and
the Image CDN all come from the Netlify environment.

### Database changes

Edit `db/schema.ts`, then generate a migration:

```sh
npx drizzle-kit generate --name what_changed
```

Migrations in `netlify/database/migrations` are applied by Netlify on deploy. Do not apply
them by hand.

### Regenerating the photos

```sh
pnpm images
```

Skips any file that already exists, so adding a recipe only renders the new one. It needs
ImageMagick's `convert` on the path: the model returns PNG, and the committed originals are
progressive JPEG at a fifteenth of the weight. Nothing links an original directly — every
`<img>` goes through `img()` in `src/lib/img.ts`, which requests an explicit width in WebP
from the Image CDN.

## Accounts

Passwords are bcrypt at cost 12. The session cookie holds a random token and the database
holds only its SHA-256 digest, so a database dump cannot be replayed as a login. The cookie
is HttpOnly, Secure in production and SameSite=strict. A wrong password and an unknown email
return the same message and take a similar amount of time. `/security` says all of this on
the site itself.
